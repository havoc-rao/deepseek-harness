# Agent Note: 0.1.5 主线合并中的本地包适配

Status: implemented

[English](2026-09-11-merge-0.1.5-local-package-adaptations.md) | 中文

## 问题

把 `offical/master`（0.1.5，3364 个提交）合并进本地主线（77 个本地提交：electron/iPad/CLI 扩展与抽取出的 toolview 包）重构了本地特性线赖以生存的全部平台：`dsh-client-runtime` 被删除（拆分为 `dsh-client-store`、`dsh-client-ui-conversation`、`api/*-controller`），`ui-conversation` 的 chat 子树移入新的 `ui-chat` 包，theme、workspaces、settings API 全部替换。Git 的 rename 检测把官方演化带进了被移动的本地文件，使整棵树哪里都编译不过：相对 import 断链、死 re-export、基于 view 的测试 fixture 对不上基于 args/metadata 的模型、本地包掉出构建聚合。

## 决策

**ui-tool-kit 吸收官方模型演化并拥有行面。** 官方继续在 `ui-tool` 的 `tool/` 子树上开发（该子树已被本地提交 54a87d68ae 抽取为 `ui-tool-kit`）；rename 检测把演化应用到移动后的副本，合并保留该结果。扁平布局将 `../models/` 修正为 `./models/`；kit 的 `/client` 入口扩到完整消费面（`readCallLine`、`formatToolBody`、terminal 谓词、`singleResultText`、`imageCardModel` 等）。两处本地扩展：`ToolRow.summarySuffix` 从 `string` 拓宽为 `ReactNode`（file-mutation 的彩色 chip 是 JSX 树；`''` 抑制行自身的纯文本 `+A -R` diffStat）；`tool.call.images` slot 声明从 ui-tool 契约移入 kit（`src/client/image-slot.ts`）——kit 的 `ToolRow` 派发该 slot 却看不到 ui-tool 的声明合并，因为 ui-tool 依赖 kit。

**ui-tool 删除自己的 edit/write 行。** 官方的 `toolviews/file-mutation-row.tsx` 与本地 `ui-toolview-file-mutation` 包注册同一组 `tool.call.toolview` 键；两处并存会对 `edit`/`write` 双重注册。本地包（含彩色 `+A -R` chip）保持唯一注册方，web-app bundle 组合重新列出 `ui-tool-kit` 与 `ui-toolview-file-mutation`。`ui-tool/tests` 中官方测试经由公开 `/client` 入口 import kit 模型。

**ui-paper 在官方 theme 缝隙上拥有全部契约。** 旧 API（`registerPaperToneLayers`、`setPaper`、`snapshot.paper`、theme 持有的 `ui-theme.paper` 设置字段）不复存在。插件现在拥有词汇表、schema 与 `ui-paper` 设置 namespace（`src/paper-settings.ts`），经 `ctx.theme.overrideTokens('ui-paper', …)` 贡献当前色调的层（重调即替换；effect teardown 持有最新 disposer），经自有绑定 scope 采纳持久化偏好，并在官方 font-size 行之后注册设置行（`order: 12`）。host 半区从自有 namespace 读色调、从 theme namespace 读主题偏好。

**消息引用插槽以 `projectUserText` 之上的 chain 存续。** 官方把内联引用渲染移入 `projectUserText` 原语；本地可扩展插槽在其上重建：原语接受 `renderReference?: (owner) => ReactNode | undefined`（undefined 即拒绝并保留内置 chip），`ui-chat` 把 `conversation.message.reference` 声明为 chain slot 并经 `ChatView`/`ChatNodeSeat`/`MessageItem` 下传。默认 chip 是原语自身的分支而非 chain 占位者，扩展以 selector 注册并可拒绝不属于它的 token 类别。

**workspace-logo 放弃**（产品决策）：其平台（apiproxy 宿主、runtime workspaces 的 `setLogo`、`WorkspaceView.logo`、三个 `sidebar.workspaces.*` 插槽、`IconCameraOutline16` 字形、HoverCard 的 `width` 扩展）在官方树中没有后继，向新 workspace-controller wire API 的完整移植超出本次合并范围。包、fixture、图标与 e2e 附加块删除；workspace-management e2e 回到官方期望。

**本地聚合恢复。** 官方的 `tsconfig.client.json`/`tsconfig.host.json` 丢掉了仅本地的包（`ui-paper`、`ui-tool-kit`、`ui-toolview-file-mutation`、`apps/electron`）；合并重新加上（否则 TS6307）。`native/landlock-run` 未恢复——其源码已删（目录只剩陈旧构建产物）。

**本地特性重新对准演化后的 API：** HMR host 重启握手重新获得官方 modules 注册表上的 `hostInstance()`；`healProfilesModuleFallback` 调用改传 options 对象；hooks 桥的 elicitation 观察者改挂 `user-questions/request` waterfall（prepend + `next()`）而非已删除的 `userQuestions/ask` 事件；`apps/cli` 显式传 `ProfileTemplate` 的 `bundles`/`patchReload`；陈旧的 `websocket-downlink` re-export 随其最后一个消费者一起消失。

## 影响

本地特性包就是适配边界：官方重构的一切整体采纳，本地线的产品特性重新对准新缝隙而不是分叉平台代码。kit 的 ReactNode `summarySuffix` 与其 `tool.call.images` 声明是对官方 `ToolRow` 仅有的两处刻意偏离；未来的官方合并会在那里显式冲突而不是无声漂移。workspace-logo 的删除在此记录，若将来在 workspace-controller API 上重建，其设计（host 记录持久化、hover 卡呈现）可从历史中找回。
