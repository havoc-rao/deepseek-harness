# Agent Note: 编辑器中的提供方所属引用标记识别

Status: implemented

[English](2026-10-15-composer-reference-tag-recognition.md) | 中文

## 问题

引用胶囊在编辑器中是原子装饰节点，但它们的纯文本形式（例如工作区引用插件生成的 `@workspace-ref/<base64url>`）只能通过菜单选择或 `insertReference` 以胶囊身份重新进入草稿。包含这类标记的文本——整段粘贴，或由其他界面注入新会话草稿——始终保持普通可编辑文字：没有胶囊、没有身份、没有提示，标签的折叠展示也从未生效。

标签语法属于其提供方（铸造标签并在消息中渲染其提及的插件），不属于 `ui-conversation` 或触发管道。把某一语法硬编码进编辑器，会往一个必须保持领域中立的数据包中塞入工作区知识，而且未来的每种标签格式都要再开一个硬编码分支。

## 决策

识别是提供方所有、同步的文本扫描，注册表挂在输入触发服务上；转换发生在编辑器自身的编辑事务内。

### 接缝

`ReferenceTagMatch`（`ui-conversation` 草稿编辑器契约）为 `{ start, end, insert }`，偏移以 UTF-16 码元计；`insert.clipboardText` 必须与匹配到的子串完全相等，这样用胶囊替换标签时所有投影偏移保持稳定（胶囊的剪贴板展开正是该标签）。`ReferenceTagParser.parse(text)` 返回文本中最早的标签，否则返回 undefined；提供方在应答前必须完整校验标签（编码、载荷、往返身份），与 `workspaceMentions` 已拒绝畸形标签的方式一致。

`ctx.inputTriggers.registerReferenceTagParser(parser)` 注册一种语法；解析器按注册顺序轮询，第一个非空结果胜出，重叠语法由注册顺序消歧。注册表与来源花名册并列存放，但从不生成候选菜单——只定义标签语法的提供方不是菜单来源。按会话的 `InputTriggerController` 通过实时注册表暴露 `parseReferenceTag(text)`（有缺陷的解析器记录日志后跳过，与有缺陷的 lexicon 来源一致），`SessionInputShell` 把它作为普通依赖接入编辑器运行时。

### 转换点

`$replaceReferenceTagsWithChips` 遍历每个文本节点，对每个节点询问解析器，切出匹配区间并替换为 `$createReferenceChipNode`。切分后的尾段在同一轮继续扫描（同一节点内的多个标签都会转换）；退化匹配（空区间或越界）结束该节点的扫描而不是死循环。转换在以下既有的 `editor.update()` 内执行：

- `paste()`——在纯文本插入之后，因此一次粘贴就是一个撤销步骤；并在 text-ref 转换提交之前，完整标签不会先退化为文件夹样式的高亮；
- `setDraft(text)`——纯文本种子路径（持久化草稿、向新会话编辑器注入的插件文本）。

`restoreDraft` 有意排除在外：其 occurrence 偏移是 `DraftSnapshot` 的权威结构化数据，扫描只会把它们推偏。`insertAsyncText`/`replaceText` 保持纯文本拼接。

### 选区

`paste()` 之后，插入后的光标以检测坐标捕获，并在转换后重新应用。标签从不移动剪贴板投影（胶囊文本 = 标签文本），因此转换前的检测偏移在胶囊替换了选区曾经指向的节点后仍然指向同一文档位置——包括恰好结束于粘贴末尾的标签，其节点否则会被替换到光标脚下。

## 备选方案

- **用 TextNode 转换做标签转换**（类似 `registerTextRefDecoration`）。否决：胶囊是原子装饰，转换在打字中途触发需要 AutoLink 式的编辑逃生通道；真实入口是粘贴与程序化种子，两者都已运行在各自的 `editor.update()` 内，可在 text-ref 转换之前确定性地完成转换。
- **把标签解析做成 `InputTriggerSource` 钩子**。否决：只定义标签语法的提供方不是菜单来源，注册它会向 `@` 菜单注入一个空候选项组。注册表与来源花名册并列存放，正是为了让识别不等于菜单参与。
- **在 `ui-conversation` 中硬编码 `@workspace-ref/` 语法**。否决：该语法归工作区引用插件所有，硬编码分支只会为某一种提供方格式向领域中立的数据包注入工作区知识。
- **也扫描 `restoreDraft` 的文本**。否决：结构化恢复的 occurrence 偏移是权威数据，重新扫描只会推偏它们；旧草稿升级需要单独的刻意通道。

## 验证

单元测试覆盖纯遍历（节点中间、整节点、相邻、跨段落与畸形标签；退化匹配终止而不是死循环）、运行时入口（粘贴与纯文本种子在一次可撤销编辑内转换；恰好结束于粘贴末尾的标签不弄丢光标；结构化恢复不受影响）以及注册表（注册顺序、首个非空胜出、延迟注册的实时花名册、fiber 释放、故障解析器隔离）。GUI 聚合测试与两个数据包套件连同这些测试一起通过；触发管道服务契约测试覆盖新增的注册面。

## 结果

粘贴包含合法标签的大段文本时，会渲染胶囊（标签、图标、原始文本提示），语义与菜单选择一致；畸形或未注册的文本原样保留。解析器注册表是两个契约成员之外唯一新增的公开面；没有注册解析器时，`ui-conversation` 不获得工作区知识，也不改变可见行为。

工作区引用插件通过新接缝注册其既有 `workspaceMentions` 语法即可选用；消息侧的 `conversation.message.reference` 槽继续负责渲染提及。
